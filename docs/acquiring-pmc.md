# PMC article packages and the browser bridge

PMC is handled through its official article-data service because its direct article-page PDF links often return HTML to automated clients. This path also retrieves the original media files that PMC makes available:

```bash
uv run sbol-visual-data download-pmc
```

PMC artifacts are checksum-verified and recorded in `data/reports/pmc_acquisition.csv`. Existing PDFs from another source are never overwritten; a different PMC PDF is stored at `pmc/paper.pdf` within the paper directory.

Some non-open PMC author manuscripts expose a main PDF on the public article page even though the article-data package provides only XML and plain text and an ordinary HTTP client receives a `Preparing to download` page. After `download-pmc`, start the conservative browser fallback with:

```bash
uv run sbol-visual-data serve-pmc-web-bridge
```

Open any public article page on `https://pmc.ncbi.nlm.nih.gov` in a browser profile that is not signed in to an NCBI account, then paste `scripts/pmc_browser_runner.js` into that tab's developer console. Enter the ephemeral token printed by the bridge when prompted; do not write it into the tracked script. For each manifest-backed author manuscript, the bridge verifies the already-downloaded PMC article XML and requires exactly one safe `self-uri` whose `content-type` is `pmc-pdf`; it constructs the canonical PDF URL without requesting the public article HTML. The queue exhausts every manifest-backed XML record before considering any record that requires live article HTML. Only records without a PMC acquisition manifest use bounded live article-HTML discovery, and those still require one unambiguous, non-supplement PDF beneath that paper's `/articles/<PMCID>/pdf/` path. PMC's public anti-bot delivery requires the browser's same-origin download-session cookie, so the runner sends ambient PMC cookies only to that exact, canonical PDF URL and rejects redirects. Loopback requests explicitly omit credentials; no PMC cookie is sent to the bridge or stored. The runner starts no more than one PDF request per second, enforces byte and time limits, and uploads the bytes to the loopback bridge. Uploaded PDFs are verified in a resource-limited child process; this bounds parser CPU, memory, and wall time but is not a privilege sandbox. The runner does not solve CAPTCHAs or other access challenges and stops after five consecutive failures. Calling `window.sbolPmcRunner.stop()` aborts its current PDF request, releases the one-shot queue claim, and makes that DOI immediately eligible again without recording a paper failure or challenge cooldown.

If either the server-side article request or the browser PDF request receives PMC's `Checking your browser`, reCAPTCHA, or `Preparing to download` interstitial, the run stops on that first response. The affected DOI is released back to the queue rather than recorded as a paper failure, the transient event remains in the append-only attempt log, and the bridge persists a 15-minute discovery cooldown in `data/reports/pmc_web_cooldown.json`. The `/next` endpoint returns HTTP 503 with `Retry-After` during the cooldown, so neither the runner nor a bridge restart can rapidly consume later records. If the runner reports `requiresBridgeRestart: true`, a queue release or in-flight `/next` transition could not be confirmed, and the bridge must be restarted before resuming. Wait for any reported cooldown and establish a normal public PMC page session before restarting; do not attempt to solve or automate the challenge.

The fallback considers only processed records with a Europe PMC PMCID and no verified `article_pdf` in `pmc.json`. For normal records, `pmc.json` must explicitly identify an author manuscript. Its one accepted local `article_xml` artifact must be bound to the pinned package metadata through canonical source and download URLs, path, byte count, SHA-256, MD5, PMCID, DOI, and manuscript ID before it can provide the PDF link. A record without `pmc.json` is queued only when the selected main PDF has a strict `nihms` filename or the public page has an explicit author-manuscript banner whose marker and visible text agree; incidental prose does not establish the version. Otherwise, the attempt is preserved as `skipped_version_unestablished` and no version is assigned. Accepted PDFs are stored as collision-safe variants under `versions/pmc_author_manuscript/`, with matching hash-named generic manifests. The manifest retains the public landing/PDF URLs and exact version evidence, pins the exact article XML or public HTML that supplied the link as an immutable hash-named snapshot, leaves the license unknown unless PMC supplied an explicit recognized license, and records that equivalence to the historically evaluated edition is not established. Because page-realm JavaScript supplies the bytes and its same-origin session affects delivery, the manifest explicitly marks the URL-to-bytes transport link as `browser_supplied_unverified`; inventory excludes these variants from verified and preferred PDF coverage until that link is independently verified. Attempts and the current snapshot are written to `data/reports/pmc_web_attempts.jsonl` and `data/reports/pmc_web_acquisition.csv`; PMC cookies are neither sent to nor stored by the bridge.
